# اختبار قبول المستخدم — بوابة الإصدار

**النسخة الإنجليزية:** [`../release-gate.md`](../release-gate.md) — وهي المرجع عند أي اختلاف.

> ⚠️ **ترجمة بحاجة إلى مراجعة قبل الاستخدام.**

**يُنفّذه:** مالك المنتج
**متى:** قبل اختبار القبول التنفيذي، لا بالتوازي معه

يغطي `REL-004`، وفحص الاكتمال الذي يشترطه `ACC-009`.

> هذا **فحص اكتمال لا اختبار**. يسأل سؤالا واحدا: هل كل ما يحتاجه التنفيذيون
> للقرار موجود؟ عرض حزمة ناقصة على التنفيذيين يهدر وقتهم ويضر بمصداقية البرنامج
> أكثر مما يضر التأجيل.

وبيانات اعتماد خارج سيطرة الفريق — وهذا جواب مشروع، وأفضل كثيرا من غيابه.

## الجزء 3 · العيوب

`ACC-009`: كل عيب حرج أو مرتفع يمس الطلب أو الدفع أو الطباعة أو المستندات
الضريبية أو الأمن أو المزامنة **مغلق أو مقبول رسميا**.

| | |
|---|---|
| حرجة مفتوحة | |
| مرتفعة مفتوحة | |
| مقبولة رسميا، ومن قبِلها | |

"مقبول رسميا" تعني أن شخصا محددا قبل خطرا محددا. لا "نظن أنه لا بأس به".
