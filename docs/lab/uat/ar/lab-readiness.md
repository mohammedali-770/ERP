# اختبار قبول المستخدم — جاهزية المعمل

**النسخة الإنجليزية:** [`../lab-readiness.md`](../lab-readiness.md) — وهي المرجع عند أي اختلاف.

> ⚠️ **ترجمة بحاجة إلى مراجعة قبل الاستخدام.**

**يُنفّذه:** فريق العمل، قبل أي اختبار آخر
**المدة:** نصف يوم تقريبا

يغطي `LAB-003`, `LAB-004`, `LAB-005`.

> **نفّذ هذا أولا.** اختبار قبول يفشل بسبب إعداد خاطئ للمعمل يهدر وقت المشاركين،
> والأسوأ أنه يعلّمهم أن النظام غير موثوق وقد لا يكون كذلك.

---

## الجزء 1 · هل يستطيع المعمل تنفيذ ما تتطلبه الاختبارات؟

| # | الفحص | جاهز عندما |
|---|---|---|
| 1.1 | ثلاثة أجهزة نقاط بيع، كلها تعمل | نعم |
| 1.2 | طابعة إيصالات وطابعة مطبخ، منفصلتان | نعم |
| 1.3 | قارئ باركود | يقرأ القسائم بثبات |
| 1.4 | جهاز دفع أو محاكٍ له | يمكن جعله يفشل عمدا |
| 1.5 | أدوات التحكم بالشبكة | يمكن حقن قطع الاتصال والتأخير وفقد الحزم |
| 1.6 | وحدة تحكم الفرع | موجودة و**قابلة للفصل** — يجب أن يكون خيارا الأجهزة قابلين للاختبار |

## الجزء 2 · حقن الأعطال

كل عطل تعتمد عليه الاختبارات، مُثبت أنه يعمل *قبل* وصول المشاركين.

| # | العطل | قابل للحقن والتكرار؟ |
|---|---|---|
| 2.1 | قطع الاتصال المركزي في لحظة مختارة | ☐ |
| 2.2 | انقطاع كهرباء الطابعة ونفاد الورق | ☐ |
| 2.3 | إغلاق التطبيق قسرا وإعادة تشغيله | ☐ |
| 2.4 | إسقاط رد الدفع بعد تنفيذه | ☐ |
| 2.5 | انحراف ساعة أحد الأجهزة | ☐ |
| 2.6 | تفعيل وتعطيل عزل الأجهزة على نقطة الوصول | ☐ |
