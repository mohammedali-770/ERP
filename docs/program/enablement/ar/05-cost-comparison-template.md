# الاستضافة والتعافي — نموذج مقارنة التكاليف

**النسخة الإنجليزية:** [`../05-cost-comparison-template.md`](../05-cost-comparison-template.md) — وهي المرجع عند أي اختلاف.

> ⚠️ **ترجمة لم تُراجع بعد من متحدث بالعربية.**

**لمن:** من يجمع عروض الأسعار
**يرفع الحجب عن:** B-05 — الفقرة 2 من بوابة موطن البيانات، الخيارات المسعّرة
**يحقق:** `PRG-010` (خيارات تكلفة متدرجة قبل أي التزام بنية تحتية) و`PRG-012`
(أهداف التعافي تُختار من طبقات مسعّرة)
**الوقت اللازم:** مستمر، مع وصول العروض
**تاريخ التحقق:** 2026-09-21

الهيكل الذي يُملأ مع وصول العروض. الملء هو العمل؛ والشكل هنا كي لا يضطر أحد
لابتكاره تحت ضغط الوقت.

---

## قراران، وهما متداخلان

**أين** يعمل النظام، و**كم من الفقد** مقبول عند حدوث عطل. فخيار استضافة رخيص مع
متطلب تعافٍ مكلف قد يكلف أكثر من العكس، ولهذا يُسعّران معا.

---

## الجزء 1 · أين يعمل

**أربعة** خيارات للتسعير. ويتوقف الاختيار على رأي قانوني طُلب على حدة — لكن
**الأسعار يمكن جمعها قبل وصول الجواب**، وينبغي ذلك.

| | الخيار | الشكل | الموطن |
|---|---|---|---|
| **أ** | البقاء كما هو | المنصة المُدارة الحالية، `eu-central-1` (فرانكفورت) | خارج المملكة |
| **ب′** | **استضافة ذاتية داخل المملكة** | **برمجيات المنصة نفسها، نشغّلها نحن على سحابة سعودية** | **داخل المملكة** |
| **ب** | إعادة بناء داخل المملكة | قاعدة بيانات وخدمات ندير تشغيلها، على مزود سحابي سعودي | داخل المملكة |
| **ج** | التقسيم | الفئات المنظَّمة داخل المملكة، والباقي كما هو | مختلط |

> **لا تتجاوز ب′ ولو كانت أحدث ما في القائمة.**
> تقول [`data-residency-gate.md`](../../../compliance/data-residency-gate.md)
> الفقرة 2 إنها "على الأرجح تستحق موضعا قبل ب"، لأن المنصة مفتوحة المصدر
> واستضافتها ذاتيا تُبقي واجهة قاعدة البيانات والمصادقة والأمان على مستوى الصف
> وطبقة التخزين كما هي — فتتفادى معظم تكلفة الترحيل التي تجعل ب مكلفا. ومقارنة
> تقتصر على أ وب تسعّر **أغلى طرفي المدى** وتُظهر القرار أسوأ مما هو.

### من يستطيع فعلا استضافة ب أو ب′ اليوم

*تم التحقق في 2026-09-21، ويستحق إعادة الفحص — اثنان منها مرشحان للتغير قبل
الإنتاج.*

| المزود | منطقة سعودية | الحالة |
|---|---|---|
| جوجل كلاود | الدمام (`me-central2`) | **حية** — عبر CNTXT |
| أوراكل كلاود | جدة، الرياض | **حية** |
| هواوي كلاود | الرياض | **حية** |
| علي بابا كلاود | الرياض (مشروع SCCC المشترك) | **حية** |
| تينسنت كلاود | السعودية | **حية** |
| أمازون ويب سيرفسز | أُعلنت مارس 2024 | **غير حية.** مستهدفة 2026، وما زالت غير مُفعّلة |
| مايكروسوفت أزور | السعودية الشرقية | **غير حية.** مستهدفة الربع الأخير 2026 |

**الخيار أ لا يستطيع ببساطة "إضافة منطقة سعودية".** فالمناطق الـ17 للمنصة
الحالية كلها مناطق AWS، وليس لدى AWS منطقة سعودية حية — أي أن ذلك المسار يحتاج
إطلاق AWS، *ثم* تبنّي المنصة. ولا أحدهما ملتزم به. سعّر ب′ لدى المزودات الحية
أعلاه.

### لكل خيار، سعّر هذه البنود

| البند | أ | ب′ | ب | ج |
|---|---|---|---|---|
| المنصة أو الاستضافة، شهريا | | | | |
| قاعدة البيانات، شهريا | | | | |
| التخزين شهريا، ونموه سنويا | | | | |

| الإعداد لمرة واحدة | | | | |
| **جهد الموظفين للتشغيل، أيام شهريا** | | | | |

> **البند الأكثر تقليلا لقيمته هو جهد الموظفين.** فالخيار أ يشمل عملا تشغيليا
> تؤديه المنصة عنا — التحديثات والنسخ الاحتياطي والتحول عند العطل والتوسع.
> أما **ب′ وب فكلاهما يعني أن أحدا لدينا يؤدي ذلك العمل**، وب′ لا تفلت منه لمجرد

### بند الترحيل، مسعّرا بصدق

الانتقال **من** الخيار أ **إلى** ب′ أو ب أو ج ليس تصدير قاعدة بيانات. سعّر كلا
منها على حدة. **ويُفترض أن تخرج ب′ أرخص بوضوح من ب في أغلب هذه البنود — فإن لم
تفعل فقل ذلك، لأنه يناقض السبب الذي أدرجها في القائمة.**

| البند | التقدير |
|---|---|
| نقل البيانات نفسها | أيام عادة |
| إعادة بناء المهام المجدولة التي تشغّلها المنصة حاليا | |
| إعادة بناء تخزين الأسرار وتدويرها | |
| إعادة بناء نموذج الصلاحيات، **وإعادة التحقق من صحته** | |
| إعادة اختبار كل شيء من طرف إلى طرف | |
| **إجمالي الترحيل** | |

> بند نموذج الصلاحيات هو الذي يستحق التدقيق. إعادة بنائه مباشرة؛ أما إثبات صحة
> إعادة البناء، لنظام يحمل رواتب وسجلات مالية، فليس كذلك.

## الجزء 2 · كم من الفقد مقبول

رقمان، بعبارات واضحة:

- **كم من البيانات الحديثة يمكننا تحمل فقدها** إذا تعطل النظام المركزي؟
- **كم يمكن أن يبقى متوقفا** قبل أن يتضرر العمل ضررا جديا؟

### ما يجعل الطبقات الأرخص أكثر دفاعا عنها من المعتاد

**الفروع تواصل البيع دون اتصال مركزي.** أجهزة نقاط البيع والطباعة والنقد وإدارة
الورديات كلها تعمل دون اتصال وتزامن لاحقا. فالانقطاع المركزي لا يوقف البيع.

ما يوقفه هو تقارير الإدارة والوظائف العابرة للفروع والتكاملات. وذلك ضرر حقيقي،
لكنه نوع مختلف عن "توقفت أجهزة البيع"، والطبقة المختارة ينبغي أن تعكس ذلك بدل
شراء حماية من عطل يستوعبه التصميم أصلا.

### الطبقات المطلوب تسعيرها

| | فقد البيانات | مدة التوقف | الشكل | التكلفة الشهرية | جهد إثبات أنها تعمل |
|---|---|---|---|---|---|
| **1** | حتى 24 ساعة | حتى 8 ساعات | نسخة احتياطية يومية، استرجاع يدوي | | |
| **2** | حتى ساعة | حتى ساعة | استرجاع لنقطة زمنية، باستعادة مبرمجة | | |
| **3** | حتى 5 دقائق | حتى 15 دقيقة | نقطة زمنية مع نسخة احتياطية دافئة | | |
| **4** | شبه معدوم | دقائق | مناطق متعددة مع تحول تلقائي | | |

### العمود الذي يُنسى

**جهد إثبات أنها تعمل.** نسخة احتياطية لم تُستعد يوما ليست نسخة احتياطية — بل
افتراض. وكل طبقة تحتاج تمرين استعادة مجدولا بنتيجة مسجّلة، وذلك الجهد المتكرر
جزء من تكلفتها.

---

## الجزء 3 · ما يُعرض على التنفيذيين

صفحة واحدة:

1. خيارات الاستضافة الأربعة بإجماليات ثلاث سنوات، وتكلفة الترحيل منفصلة
2. طبقات التعافي الأربع بتكاليفها الشهرية
3. توصية، مع تسبيبها
4. **ما لا يزال مجهولا** — مذكورا لا مُلطَّفا

---

## ملاحظة على التسلسل

قرار الاستضافة يحتاج الرأي القانوني. **أما الأسعار فلا.** اجمعها الآن، فحين يصل
الرأي يستغرق القرار اجتماعا بدل ربع سنة.
